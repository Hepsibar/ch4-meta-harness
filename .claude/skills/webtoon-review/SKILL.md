# 웹툰 검수

검수의 목적은 얼핏 맞아 보이지만 실제로 어긋난 부분을 찾는 것이다. 각 산출물을 따로 보지 말고 **교차 대조**한다. 점검 축을 나눠 한 관점에서 놓치는 오류를 잡는다.

## 1. 점검 축

| 축 | 무엇을 대조하나 | 대표 문제 |
|------|----------------|-----------|
| 개연성 | 바이블 ↔ 시나리오 | 인물 행동이 동기와 어긋남, 설정 모순 |
| 설정 연속성 | 바이블 ↔ 이번 화 ↔ 앞 화 | 이름·관계·세계관 규칙이 화마다 다름 |
| 작화 일관성 | 캐릭터 토큰 ↔ 컷 프롬프트 ↔ 이미지 | 같은 인물이 컷마다 다른 외형/색 |
| 스크롤 가독성 | 콘티 | 컷당 정보 과다, 시선 꼬임, 템포 늘어짐 |
| 대사-그림 정합 | 시나리오 대사 ↔ 콘티 말풍선 ↔ 이미지 | 대사와 표정·동작 불일치, 말풍선 누락 |
| 누락 | 콘티 컷 ↔ 생성 이미지 | 컷에 이미지 없음, 참조 안 된 캐릭터 |

## 2. 누락은 수치로 확인

파일 존재만 보지 않는다. 콘티의 컷 번호와 실제 이미지 파일을 대조한다.

```bash
# 콘티의 컷 번호
grep -oE 'cut_[0-9]+' _workspace/03_director_storyboard.md | sort -u > /tmp/cuts.txt
# 생성된 이미지
ls _workspace/04_images/ | grep -oE 'cut_[0-9]+' | sort -u > /tmp/imgs.txt
# 콘티에는 있는데 이미지가 없는 컷
comm -23 /tmp/cuts.txt /tmp/imgs.txt
```

차이가 나오면 미생성 컷으로 보고한다.

## 3. 판정 기준

- **PASS** — 문제 없음.
- **FIX** — 소규모 수정(대사 다듬기, 말풍선 위치, 프롬프트 토큰 한 줄)으로 해결.
- **REDO** — 재작업 필요(장면 재구성, 컷 재생성, 캐릭터 외형 불일치).

애매하면 REDO로 올리지 말고 FIX로 두되 근거에 불확실성을 적는다. 과잉 재작업은 비용이 크기 때문이다.

## 4. 보고서 형식

`_workspace/05_review_report.md`:

```
# {작품} {N}화 검수 보고서

## 요약
- 점검 컷 수 / 전체 컷 수 (샘플이면 제외 범위 명시)
- PASS n · FIX n · REDO n
- 미생성 컷: cut_0xx, ...

## 지적 사항
| cut | 축 | 판정 | 근거 | 담당 |
|-----|-----|------|------|------|
| cut_012 | 작화 일관성 | REDO | 주인공 머리색이 시트(검정)와 다름(갈색) | art-director |
| cut_030 | 대사-그림 | FIX | 말풍선 "웃지 마"인데 표정이 미소 | director |

## 누락
- cut_045: 콘티에 있으나 이미지 없음 → art-director

## 종합 의견
- 다음 우선순위로 수정 권장: ...
```

## 5. 원칙
- 원본 산출물을 고치지 않는다. 보고서만 쓴다. 수정은 각 담당 에이전트가 맥락을 유지한 채 해야 정확하다.
- 모든 지적에 컷 번호·근거·담당을 단다. 담당이 없으면 리더가 배분할 수 없다.
- 전수가 아니라 샘플만 봤으면 그 사실과 제외 범위를 요약에 밝힌다.
